# Wrong-code census

RQ-91-WRONGCODECENSUS (Refs #1741), the week-one census of the v0.92 plan's
Bet A ("wrong code, with a number").

## What is counted

Every issue that was open on the measurement date was read in full, not by
its title, and put in exactly one class:

- **wrong-code**: synth exits 0 and its output is wrong. That covers a wrong
  value, a call bound to the wrong function, a spurious trap, or an
  instruction the declared target cannot execute.
- **loud decline / missing feature**: synth refuses, or a feature is absent.
  A refusal is reach, not wrong code.
- **machinery / docs / tooling**: CI, release gates, process, documentation,
  and tools that print wrong text without emitting wrong code (#1704, the
  disassembler listing).
- **unclear**: no defined right answer to compare against. #1207 is an
  invalid module, which has no semantics to be wrong about. #1450 is a
  multi-result return convention that no contract states.

Each wrong-code issue's own repro was then run on the census commit. Its
status is one of the following:

- **LIVE-WRONG**: still wrong.
- **FIXED**: correct now. Most of these are fixed on main but the issue stays
  open, because closure happens at release; they are the closure candidates.
- **NOW-DECLINES**: refused loudly now.
- **CANNOT-REPRO**: no runnable repro.

## How it is re-run

```sh
# the measured rows (kiln + unicorn); SDKROOT is needed on macOS for unicorn
SYNTH=$PWD/target/debug/synth cargo test -p synth-oracle --features exec \
  --test wrong_code_census -- --nocapture
# the table below against the census rows (no engine, part of the Test job)
cargo test -p synth-oracle --test wrong_code_census
```

The table below is generated from `CENSUS` in
`crates/synth-oracle/tests/wrong_code_census.rs` and checked byte-for-byte.
Each measured row asserts its status exactly, both ways. A fix turns a
LIVE-WRONG row red, and a regression turns a FIXED row red. To record either,
edit the row and re-bless with `WRONG_CODE_CENSUS_BLESS=1`.

There are three kinds of evidence:

- **exec**: the issue's repro runs on kiln and on unicorn through
  `synth_oracle::run_case`.
- **structural**: the test reads the property the issue names from the
  emitted object. This is used for an import call, a link-time binding,
  AArch64 code (the harness emulates only ARM and RV32), an ISA extension,
  and two library APIs.
- **a named `scripts/repro` oracle**: the issue's shape needs linear memory
  and a link step, which the Rust harness does not provide yet. That oracle
  already pins the shape exactly, it is CI-wired, and its run on the census
  commit is the evidence. It is not re-run by the Rust test.

## Limits, stated

- **#1691**: the census runs the reduced integer shapes from the issue's own
  fixture, `scripts/repro/if_arm_dead_value_1691.wat`, on cortex-m4. The
  reporter's float attachment (`repro.zip`, cortex-m7) was not re-run, and
  the harness refuses float signatures.
- **#1710, #1711**: reported on cortex-m4f and cortex-m7dp. The integer code
  was run on the cortex-m4 model.
- **#1696, #1699, #1747, #1745**: these are structural. Each status is a
  property of the bytes, and the issue body records the executed wrong value
  behind that property. A changed byte sequence turns the row red for
  re-measurement. It does not count as a fix.
- **Default flags** means `--target cortex-m4` with no other codegen flag
  (`--all-exports` only selects which functions are emitted). It is the
  population behind Bet A's zero target.
