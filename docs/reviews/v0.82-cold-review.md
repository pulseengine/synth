### F6 is the one that mattered: a safeguard that could not fail

`compliance.yml`'s externals-sync step reported `synced N of N` with **rc=0 while every external
directory was empty** — the single condition it existed to refuse. Two independent causes:

- `dest.exists()` treated directory **existence** as a synced external;
- the non-vacuity check compared `len(cloned)` against `len(ext)`, and `cloned` was **appended to
  by the loop it guarded**. A counter the loop increments can only ever *equal* the population,
  so the refusal was **unreachable by construction**.

The fix re-derives the count by **reading the filesystem back** after the loop, giving the check a
source independent of what it checks. Gated by `scripts/test_compliance_sync.py`, which extracts
the **shipped heredoc** rather than a copy, and wired into `claim-check` — a required context,
because a check in no workflow is not a gate.

## A finding about the merge ritual itself, from this release's own theme

A **cancelled** check-run answers "no" to both merge gates: CHECK3 asks for zero non-advisory
*failures* and cancelled is not a failure; CHECK3b asks for zero non-advisory *pending* and
cancelled is completed. So both pass while the oracle ran **zero steps**. Measured on this
release's own PR #1493: `Mach-O host-link oracle, NATIVE arm64-macOS (RQ-64-MACHO)` reported
`cancelled` with `runner=` empty and `steps=0` — a **runner no-show** — and the ritual printed
GATEOK. Reading rc without a pipe, `grep -i -E 'cancel|timed_out'` returns **rc=1 with zero
hits** in both `scripts/merge_ritual.sh` and `scripts/tag_release.sh`; the only refusal lives in
a hand-run guard, outside the repo and outside CI.

That is "satisfying one gate can arm another" inside the machinery built to enforce it. A gate
set written as "zero X plus zero Y" has a third state it never names, and the check-run domain
has five more. Filed as v0.83's CANCELGAP lane.
