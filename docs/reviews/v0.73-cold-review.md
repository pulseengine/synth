## Gate findings, and the fix for each

### F1 — a typo'd issue reference was silently absorbed

`stale_pin_check.py` booked any value with no exact `^#\d+$` match as
"reason-charged". The `attributed + reasoned == declared_total` invariant —
built precisely to prove no pin is skipped — still balanced, so the gate printed
PASS while never checking that issue for closure.

Reproduced: `('#1206', 2)` → `('issue #1206', 2)` in the parity table drops
#1206 from the checked set (8 issues → 7, attributed 68 → 67, reasoned 17 → 18,
total still 85).

The anchored regex is RIGHT and stays — `#539-grow-fails` must not read as issue
539. What was missing is that the reason bucket was a catch-all. It is now a
DECLARED set of exactly two strings, enumerated from the live tables, and any
other value carrying a `#N` is refused by name.

### F2 — a null stub passed the falcon oracle's entire CI step

`falcon_opt_1318_differential.py` inferred "compiles" from the ABSENCE of a
`warning: skipping` line, never read the return code, and wrote the object to
`/dev/null`. A 14-line shell stub printing the six expected warnings and exiting
3 satisfied the whole step — `oracle_run.py` floor included, because
`compiles >= 3` counts INVOCATIONS, not successful compilations.

The six cells at risk were the CONTROLS: the i32 and AArch64 cells that prove
the oracle still discriminates. The exit status must now agree with whether
anything was skipped, and a clean compile must produce a non-empty object.

### F3 — the verdict that detects #1269 ask 2 was never exercised

Both `squash_fidelity` calls in `--self-test` passed `(x, x, base)`, so
`diff_lines` was always 0 and the `SQUASH ALTERED CONTENT` branch was
unreachable from the fixture. Replacing `if diff_lines == 0:` with `if True:` —
deleting the detection outright — left the self-test green.

This is the live path: `merge_ritual.sh` calls it after every merge. A
current-branch-with-nonzero-diff case now exists, and fails on that mutation.

### F8 — the deadlock guard never asked whether the target pool can run the job

Its scope is "defined / has `runs-on` / no `if:`" — all properties of the job's
DECLARATION. Moving a required context to self-hosted produced ZERO deadlock
failures; it red only on the RATCHET, and lowering the ceiling exactly as the
ratchet instructs gave "0 failure(s)".

**And the artifact's stated reason was wrong for half the set.** RQ-73-CIPOOL
says the four required contexts "can NEVER move" because `no_new_privs` forbids
`apt-get`. Measured on this tree, only TWO need apt (`Test`, `Z3 Verification`);
`Kani Verification` and `Bazel Build & Proofs` do not, and five required
contexts already run self-hosted today. The true statement is narrower — a
required context that needs apt can never run self-hosted — and that is what the
new check enforces. The general claim is false and would eventually license
"working around" a blocker that was never there.

## DEFERRED, with the mutation that demonstrates each

Recorded rather than rushed: six gate changes in the commit before a tag is how
v0.72's second miscompile arrived, inside the fix for the first. Each of these
has an executable reproduction and is a v0.74 candidate.

- **`merge_gate.decide` CHECK1 cannot see a NEVER-REPORTED context.** Mutation:
  `roll.get(r)` → `roll.get(r, "SUCCESS")`. `--self-test` stays green, because
  every CHECK1 case either has all nine present or fails the set comparison
  first. `decide({}, list(REQUIRED_CONTEXTS), True, 0, True)` then returns
  CHECK1=True — an empty rollup, which is the never-reporting deadlock
  `ci_pool_tripwire` exists to prevent. The code is right; the test is blind.
- **`--squash-fidelity`'s exit mapping has no case.** Mutation:
  `return 0 if verdict == "FAITHFUL" else 1` → `return 0`. `--self-test` stays
  green because `self_test()` never calls `main()` — and `main()`'s exit code is
  the only thing `merge_ritual.sh` consumes. Same shape as round 1's F3, one
  level out.
- **`APT_RE` is blind to apt in a script file and to `apt` without `-get`.** The
  inline case is CAUGHT (verified: moving a required context to self-hosted with
  inline apt exits 1). Moving the same apt lines into
  `run: bash scripts/install-llvm-dwarfdump.sh`, or writing `apt install`
  instead of `apt-get install`, both leave the tripwire at rc=0. Not
  hypothetical: `scripts/install-qemu.sh` already contains `apt-get`. No
  `uses: ./` exists in `ci.yml`, so the composite-action vector is latent.
- **A null stub still passes the falcon oracle's entire CI step.** Round 1 added
  an exit-status cross-check and an object existence/non-empty check; a 16-line
  stub that exits 3 when it declines and writes a ONE-BYTE file when it does not
  satisfies both, and the full CI step exits 0. The object is never checked for
  being an ELF, for `EM_AARCH64`, or for a `.text`. Structural sub-finding: the
  object check sits inside `if not declines:`, and on arm and riscv something
  ALWAYS declines, so for those backends the branch is unreachable and the i32
  CONTROL cells are inferred purely from the absence of a warning line.
- **`FIELD_KEYS_DERIVED` sees one syntactic shape of one binding in one module.**
  The AST walk requires `fields.get("literal")`. A subscript, a non-literal key, a
  differently-named local, or a read in another script all escape — live instance:
  `loop_conformance_check.py` reads `(a.get("fields") or {}).get("issue")`, a
  shape this walk cannot see. `FIELD_KEYS_UNREAD = {"carried-from"}` is honest
  and bounded; the undisclosed part is the SHAPE narrowness.
- **The census check cannot see population shrinkage.** Moving 7 of 8 v0.73
  artifacts aside leaves `_cut` correct and the census silent; the red comes
  entirely from R10, and only because those artifacts already have delivery
  commits. At planning time the same shrink fires nothing. GATETRUTH's fix is
  correct about the failure mode it covers and does not replace what the old
  vacuous pin claimed to cover.
