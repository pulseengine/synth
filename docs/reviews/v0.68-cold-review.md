## Findings, and what was done about each

**F1 — a false sentence inside RQ-68-CLAIMSDRIFT (BLOCKER).** The artifact's
own prose said "Status stays `proposed` with `disposition: partial`", while the
artifact is `status: implemented` with no disposition. This is exactly the
class STATUSGATE was built for, and exactly the part it cannot see: R11 reads
the structured fields, so prose that contradicts them stays invisible. FIXED
before tag — the sentence now states the real status and names PR #1313. The
reviewer also established that R11 is not vacuous, by deleting SUBTRACT's
`disposition` in a copy and watching `FAIL R11 RQ-68-SUBTRACT`.

**F2 — the lever population was 37, not 36 (BLOCKER by this project's own
rule).** The census enumerated every `env::var("SYNTH_…")` read outside tests
and found 36. One more variable is read through a constant —
`SYNTH_HOME_ALIAS_AUDIT` via `home_alias::AUDIT_ENV`, reached from shipped
`select_with_stack.rs` — so the literal-name grep could not see it. FIXED
before tag in both the artifact and the CHANGELOG: 37 are read, 36 by literal
name, and the census set those 36. What shipped is unaffected: the SBOM records
`SYNTH_*` by prefix rather than from a list, and the determinism gate scrubs
the whole prefix, so the 37th is recorded and controlled like the rest. The
defect was in the count, not in the mechanism — which is the argument the
artifact makes for recording by prefix, now demonstrated against itself.

**F3 — NOPCLASS's own classification did not add up.** The record said "12 are
legitimate" and then listed 1 + 7 + 2 + 1 = 11. Three of the seven IT/ITE
opcode-base sites are also in the f32/f64 helper encoders, not in
`encode_thumb` itself. FIXED before tag: 11, with the split named. The
load-bearing half — seven silent fallbacks, all now returning a typed error —
was independently confirmed at v0.67.0 and at the release commit.

**F4 — the plan file said the audit filed "21 issues (#1272-#1294)".** The
range holds 23, all real, all mapped. The CHANGELOG's 23 was right; the plan's
comment was stale from before the audit finished filing. FIXED before tag in
all three places.

**F5 — `determinism_check.py`'s docstring described normalisation the code does
not do.** It claimed the output file name "is normalised"; the comparison is
raw (`if sa != sb`). The result is still correct, because both builds write the
same base name into different directories and the SBOM records only the base
name. FIXED before tag by describing what the code actually does and why that
is sound — a docstring that claims a defence the code does not have is the
same class this release is about.

**F6 — one "not silicon" site survived the cut-time sweep.**
`scripts/repro/mem_isolation_red_1145.py` still described gale's containment
evidence as "emulation, not silicon", which was true of the Renode run it
describes but omits the later STM32WB55 result. FIXED before tag by recording
both runs.

**F7 — the "found this release" list was incomplete.** #1303 was missing (the
across-call VFP checker stops at an op it does not model — the path the 25
re-classified MVE ops now take), and #1301 was described as its MPU-minimum
detail rather than as the whole missing ARMv6-M profile. FIXED before tag.

**F8 — "`pmp` … is never an alias" was true only at the CLI.** `synth-core`'s
`SafetyBounds::parse` still maps `pmp` to `Mpu`, pinned by a unit test, and
`synth-core` is published; and on AArch64 the `pmp` refusal comes from the
older #865 check, whose message names `mpu`. Both reproduced on the release
binary. The CHANGELOG sentence is narrowed to what is true, and the residual is
filed as **#1317** for v0.69 with a red-first shape. Not fixed in code at the
cut: it changes a published crate's parse behaviour and its pinned test, which
is a v0.69 change, not a release-note correction.

**F9 — the survey's `reanchored_at` named a commit its positions did not
match.** The re-anchor ran on the release tree before the release commit
existed, so it recorded `519a9079` while the recorded positions matched the
release commit. FIXED before tag by re-running the re-anchor on the committed
tree: 0 sites moved, 0 not found, and a leaf-walk shows `meta.reanchored_at` as
the only changed key.

**F10 — a pre-existing FEATURE_MATRIX row implied Cortex-M55 was different.**
It said SIMD functions "loud-skip on all other targets", implying M55 lowers
them. It does not: a `i32x4` module is refused at decode on cortex-m55 exactly
as on cortex-m4, which is what SUBTRACT measured from the other side. FIXED
before tag in the template, and the matrix regenerated from it.
