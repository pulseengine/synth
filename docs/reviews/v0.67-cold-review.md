## Findings, and what was done about each

**F1 — all seven artifacts were `status: proposed`, and RQ-67-VFPREACH had
neither `landed:` nor `verified-by:`.** The release claimed "five implemented"
while no artifact carried a claiming status. The reviewer established why the
gate stayed green rather than guessing: with `proposed` + a `manual:`
done-when, R2 and R3 are both structurally inert, so the over- and
under-report rules were disarmed for the entire release's artifact set. This
was the third instance of a class v0.66's own cold review had already filed.

FIXED before tag. The five delivered artifacts are now `implemented`;
RQ-67-SUBTRACT (refuted) and RQ-67-ARCHMODEL (deferred) stay `proposed`
because neither requirement was met. Flipping the status immediately re-armed
R2, which then failed on two artifacts with no `verified-by:` — the gate
working as designed the moment it was given something to bite on.
RQ-67-VFPREACH gained a full `landed:` recording what shipped, the 621/621
byte-identity, and **the half of its own done-when that is unmet**: the
reporter's module is unobtainable, so the tick's function count is unpublished
rather than estimated, and the proxy fixtures were withdrawn rather than
reported. RQ-67-CALLEESAVE gained a `verified-by:` naming which issues closed
by measurement and which did not.

**F2 — "Every number below is printed by `claim_check --metric`" was false for
two columns.** The v0.66.0 column and the delta are a previous-release
comparison the tool does not print (its own delta is against the ratchet
baseline). The numbers were right; the provenance sentence was not — and
RQ-67-NOTESGATE's own done-when demands the notes quote printed numbers.

FIXED: the provenance is now stated per column.

**F3 — the `last changed` / `held` columns described the previous release.**
`ratchet_value_history()` seeded its comparison from the newest *tag*, so the
working tree was invisible to it: a value that fell 127 → 85 in the tree being
tagged still printed "last changed v0.66.0, held 1", contradicting the delta
two cells to its left. The reviewer also found the section carrying two
counting conventions at once — `held 8` for a value v0.67 is the ninth release
to carry, eleven lines from a "ninth release without a fall" that counts the
cut.

FIXED in the tool, not just the prose: the helper now compares against the
derived live values and prints `(this release)` when a value moved in the tree
being cut, and `held` counts releases **including** the one being cut, one
convention throughout. This is a defect in machinery this release shipped,
found by the review the machinery was built to support.

**F4 — "16 i32 `_imm` rules" was wrong; there are 15.** Five ALU forms and ten
comparison forms. The error originated in the v0.67 plan, propagated into
RQ-67-SUBTRACT and into the release notes, and no gate covers it: the
`sel_dsl_rules` ratchet counts total manifest lines, never the `_imm` subset.

FIXED in all three places, with the correction stated rather than silently
applied. It does not change the refutation, which turns on i64 carrying zero
rules and on there being no i64 fold to dispatch from.

**On finding 10 (not a defect, recorded for accuracy):** ARCHMODEL artifacts
exist for v0.63 onward — five files, with internally consistent self-declared
ordinals. Recurrences one and two (v0.61, v0.62) predate the artifact, so
"seventh consecutive" rests on prose in the v0.63 artifact rather than on
repo-derived evidence. The external blocker is real and was re-verified at
cut: spar#445 OPEN, last updated 2026-09-03.

**On finding 8:** the 621 denominator is re-derivable (207 fixtures × 3
configs, and `git ls-tree` confirms 207 at four separate revisions). The
byte-identity *result* lives in commit messages and a waiver reason, not in a
re-runnable harness — ASSERTED, and labelled as such here. "No corpus module
reaches the rung" is recorded in a shipped source file's header alongside four
real tests.
